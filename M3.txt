docs: the fork's own URLs say printhok

Ahead of renaming the repository from `DeWarePeb/bambuddy` to
`DeWarePeb/printhok`. Seventeen references across the README, `UPDATING.md`, the
AGPL modification notice, the three docs under `docs/printhok/`, the bug-report
message and one outbound User-Agent.

Only the fork's own URLs move. `maziggy/bambuddy` is untouched everywhere it
appears, which is most of them.

**The install path, the systemd service, the service user and the HTTP API stay
`bambuddy`.** That is the point of doing this as a rename of the repository and
nothing else. Renaming those means editing upstream's own files, and every line
of upstream a fork edits is a line it re-resolves on every rebase — the opposite
of tracking upstream closely, which is the plan. The UI has said Printhok since
`f0e87a61` and it does it through `brand.json`, without touching a single
upstream string; this follows the same rule.

So `git clone …/printhok.git /opt/bambuddy` looks mismatched and is correct:
the repository is Printhok, the application it installs is still Bambuddy's.

GitHub redirects the old URLs indefinitely, so nothing breaks for anyone who
already cloned. The README says so, and gives the `remote set-url` for people who
would rather not depend on a redirect. The notice records the former name,
because that file exists to identify the repository.
